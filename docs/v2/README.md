## 2. Коротко о целевой картине

1. **Управление сервером — через веб-панель по HTTPS.** SSH нужен для
   первоначальной установки и аварийного восстановления, а не для повседневной
   работы.
2. **Бэкапы — на панели.** Список и скачивание публичны, без авторизации.
   Из клиента работа с бэкапами убрана.
3. **Клиент — простой и кроссплатформенный.** Windows 10/11 и Linux через
   Proton, один бинарник, мастер без терминала.
4. **Один административный писатель.** В `configs/`, `players/`, `world/`,
   `mods/` и `backups/` пишет только `ops`. Панель читает и вызывает ops.
5. **Три контейнера:** `tes3mp`, `panel`, `backup`. `nginx`, `export` и
   `certbot` отсутствуют.

## 3. Принятые решения

| Решение | Почему | Где детали |
|---|---|---|
| Серверная часть и клиент на Go | Один язык, статические бинарники, хорошая тестируемость | 02, 04, 06 |
| Ops — отдельный CLI, панель вызывает подпроцессом | Один писатель, аварийный доступ, стабильный JSON-контракт | 04 |
| Три контейнера, `panel` и `backup` — один образ | Меньше движущихся частей; бэкапы идут без панели | 02 |
| HTTPS по IP, Let's Encrypt, без домена | Не требовать DNS от домашнего сервера | 05 |
| Один админ и один пароль, Argon2id | MVP для одного человека, без ролей и приглашений | 05 |
| Публичные бэкапы и текущий архив модов | Переносимость данных — цель проекта | 01, 05 |
| Клиент на Fyne, логика отдельно от UI | Кроссплатформенность и тесты без окна | 06 |
| `state deploy` через staging + rename | Не терять текущее состояние при битом архиве | 04 |
| Старые клиентские конфиги не мигрируются | Меньше legacy-кода; чистая установка проще | 06 |

## 4. Ветки и порядок работ

Основная ветка — `master`. Работа идёт в интеграционной `v2`, от неё создаются
ветки подсистем, от подсистем — ветки задач.

```text
master
└── v2
    ├── v2-docs
    ├── v2-infra
    ├── v2-ops
    │   ├── v2-ops-contracts
    │   └── v2-ops-mutations
    ├── v2-panel
    │   └── v2-panel-auth
    └── v2-client
        └── v2-client-installer
```

Важно: в Git нельзя одновременно иметь `v2/ops` и `v2/ops/contracts` — это
конфликт refs. Поэтому имена плоские: `v2-ops`, `v2-ops-contracts`.

Правила:

- `master` защищена; изменения только через merge из `v2` на milestone.
- `v2` — интеграционная ветка, всегда собирается и проходит тесты.
- Ветка подсистемы создаётся, когда начинается параллельная работа. Если работа
  идёт последовательно, задача может ветвиться прямо от `v2`.
- Задача живёт 1–3 дня, затем PR в подсистему, подсистема — в `v2`.
- Milestone-теги: `v2-m0-docs`, `v2-m1-ops-read`, `v2-m2-ops-write`,
  `v2-m3-panel`, `v2-m4-client`, `v2-m5-cutover`, `v2-m6-packaging`.

Порядок из `02-architecture.md` §9:

1. Контракты и тесты.
2. Ops только чтение.
3. Ops мутации.
4. Панель MVP.
5. Клиент MVP.
6. Вырезание старого.
7. Перенос `package.sh` на Go.

## 5. Правила ведения документации

- Документ без статуса и даты считается черновиком.
- Контракты (JSON, коды, форматы, API) живут только в `03-contracts.md`.
  Остальные документы ссылаются на разделы, а не копируют схемы.
- Меняешь контракт — меняешь фикстуры и тесты в том же PR.
- `docs/legacy/` не обновляется. Если оттуда что-то нужно, переносим в
  `docs/reference/` или в новую доку.
- `docs/reference/` — справочники по TES3MP, а не описание нашей архитектуры.

## 6. Старые документы

- `docs/legacy/` — старые гайды по SSH/nginx. Оставлены только для истории
  миграции; после v2-MVP удаляются.
- `docs/reference/modding.md` — ограничения TES3MP 0.8.1, актуальны.
- `docs/reference/tes3mp-settings.md` — reference по `config.lua`, актуален.
- Старые `docs/development/*` удалены: они описывали bash-клиент и
  `nginx`/`export`.

## 7. Что считается готовым

Документация готова к реализации, когда:

- у каждой команды ops есть JSON-форма и код ошибки в `03-contracts.md`;
- у каждого публичного HTTP-маршрута есть схема ответа и поведения при ошибке;
- форматы `mods` и `state` описаны один раз и совпадают с фикстурами;
- в `07-testing.md` есть проверка на каждый контракт и каждый failure mode;
- в `08-runbook.md` есть действия для потери пароля, битого архива, нехватки
  места, недоступного Docker и сломанного TLS.

После этого можно начинать `v2-ops-contracts` и `v2-ops-read`.

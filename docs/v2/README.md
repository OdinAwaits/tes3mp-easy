# TES3MP Easy — документация

Это единственный комплект архитектурной документации проекта. Документы
описывают текущее состояние серверной части, клиента, контрактов и
эксплуатации. История изменений и причины прошлых решений — в Git, а не в
этих файлах.

## 2. Коротко о схеме

1. **Нативный запуск на systemd.** `tes3mp.service`, `tes3mp-panel.service` и
   `tes3mp-easy-backup.timer`; без контейнерного рантайма и файлов оркестрации.
   Релизный архив ставится одним `bootstrap.sh` и уже содержит оба бинарника.
2. **Управление через HTTPS-панель.** SSH нужен для установки и аварийного
   восстановления, а не для повседневной работы.
3. **Бэкапы — state каждые 15 минут.** Моды и состояния — публичные архивы без
   логина. В state входит только `config.lua`; пароль сервера и banlist в него
   не попадают. State-бэкапы идут каждые 15 минут, дневная история хранится
   бессрочно. `doctor` предупреждает при свободных <1 GiB и блокирует мутации
   при <512 MiB, но не останавливает игру. Дашборд показывает RAM/CPU игры и
   системы за 1 ч/6 ч/24 ч без отдельной БД.
4. **Один административный писатель.** Административные изменения в `configs/`,
   `players/`, `world/`, `mods/` и `backups/` вносит только `ops`; сам
   `tes3mp.service` пишет `players/` и `world/` во время игры. Панель читает и
   вызывает ops от `tes3mp` через узкое sudo-правило.
5. **Клиент — простой и кроссплатформенный.** Windows 10/11 и Linux через
   Proton, один бинарник, мастер без терминала.

## 3. Принятые решения

| Решение | Почему | Где детали |
|---|---|---|
| Серверная обвязка (ops/panel) и клиент на Go | Один язык, статические бинарники, тестируемость | 02, 04, 05, 06 |
| Запуск через systemd, без контейнерного рантайма | Меньше фоновой памяти и узкая модель привилегий | 02, 08 |
| Ops — отдельный CLI, панель вызывает подпроцессом | Один писатель, аварийный доступ, стабильный JSON | 04 |
| `tes3mp` и `tes3mp-panel` — разные пользователи | Игра не получает доступ к паролю, панель — к записи мира | 02 |
| Sudo только на ops и фиксированный rootctl | Панель не root, ops не получает произвольный shell | 02 |
| Встроенный ACME: сертификат Let's Encrypt для публичного IP | Панель работает без внешнего прокси и ACME-клиента | 05 |
| Один админ и один пароль, Argon2id 32 MiB/1 поток | Для одного человека и бюджет 64 MiB | 05 |
| Публичные архивы модов и состояний | Переносимость данных — цель проекта | 01, 05 |
| Метрики RAM/CPU — кольцевой буфер в памяти панели | Без БД и экспортёров, ~0.6 MiB на 512 MiB VM | 02, 05 |
| State и моды только в поддерживаемых форматах | Один формат, проще валидация и тесты | 03 |
| Retention: 15 минут, дни, недели, месяцы навсегда | Долгая история без ручного труда | 03, 04 |
| Клиент на Fyne, логика отдельно от UI | Кроссплатформенность и тесты без окна | 06 |
| Никакой миграции старых конфигов и архивов | Чистая установка проще и безопаснее | 01, 03 |

## 4. Правила ведения документации

- Документ описывает только текущее состояние. Статусы, даты, номера задач,
  планы, отчёты о выполнении и обращения к прошлым реализациям не ведутся.
- Контракты (JSON, коды, форматы, API) живут только в `03-contracts.md`.
  Остальные документы ссылаются на разделы, а не копируют схемы.
- Меняешь контракт — меняешь фикстуры и тесты в том же PR.
- `docs/reference/` — справочники по TES3MP, а не описание нашей архитектуры.
- `test/docs` проверяет локальные ссылки, валидность JSON-примеров, отсутствие
  дублированных схем и устаревших имён backend-ов.

# W06 — `staff set`, `config get/set`

- Сделано: `staff set --player <name> --rank 0..3` меняет только
  `settings.staffRank` в `players/<name>.json`, сохраняет остальные поля и не
  создаёт отсутствующего игрока. Имя проверяется через `pathguard.Base`
  (exit 8), битый JSON или не-объект `settings` — `config_invalid` (exit 9).
- `internal/gameconfig` читает `configs/tes3mp-server-default.cfg` (INI),
  `configs/config.lua` и `configs/banlist.json`, отдавая только известные
  ключи; таблицы и списки `config.lua` попадают в `read_only`.
- `config set` принимает только whitelist, проверяет тип и диапазон, меняет
  одну строку/значение и сохраняет полнострочные и inline-комментарии, а также
  CRLF. Для server alias `enabled` нормализуется в `masterServerEnabled`.
- Banlist принимает JSON-массив или по одному значению на строку, проверяет
  имена и IP; остальные ключи запрещены.
- Перед записью создаётся `<path>.bak-<UTC timestamp>` (при совпадении —
  суффикс `-NN`), затем `atomicfile.WriteFile` заменяет файл с сохранением
  прав. Symlink и отсутствующие файлы отклоняются.
- `config get` lock не берёт; `config set` берёт exclusive `flock`, а
  `--dry-run` — shared и не пишет ничего. Обе мутации возвращают
  `restart_required: true` и не перезапускают сервер.
- Проверено: unit-тесты `internal/gameconfig` (чтение, типы, диапазоны,
  комментарии, read-only таблицы, alias, `.bak`, collision, dry-run, symlink,
  отсутствующие файлы, banlist), unit-тесты команд (разбор аргументов, mapping
  ошибок, human output, `locked` без изменений, unsafe player, backup collision
  и сбой записи) и contract-тесты реального бинарника (точные JSON-ключи,
  `config_invalid` с `file`/`key`, exit 2/3/8/9, human output, неизменность при
  `--dry-run`, сохранность чужих полей player JSON);
  `go test ./... -count=1`, `go test -race`, `gofmt`, `go vet`, `go build`.
- Ограничение: таблицы и списки `config.lua` в MVP только показываются в
  `read_only` и не редактируются.

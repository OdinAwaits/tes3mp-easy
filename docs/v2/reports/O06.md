# O06 — Contract-тесты read-команд

- Сделано: сквозной contract-набор `test/contract/ops/read_commands_test.go`
  для `status`, `logs`, `backups list` и `doctor` на реальном бинарнике и
  полном temp-root.
- Envelope: точные ключи `ok`/`data` и `data` каждой команды, отсутствие
  `backend`/`error` в успехе, пустой stderr, ровно один JSON-объект.
- Read-only: снимок temp-root до и после серии совпадает, `.locks/ops.lock`
  не создаётся. При удержанном эксклюзивном `flock` и `--lock-timeout=1ns`
  все четыре команды завершаются с exit 0.
- Границы: `status`/`logs` не читают data root даже при `--root`, указывающем
  на обычный файл; `--root`/`--json` после команды работают для всех четырёх.
- Доступность: `status`/`logs` при недоступном systemd/journald — exit 6
  `service_unavailable`; `doctor` — exit 10, `ok: true`, без `error`;
  `backups list` не вызывает systemctl/journalctl.
- Help: `backups list` перечислен как реализованная read-команда, остальные
  команды явно отмечены как незавершённые.
- Проверено: `gofmt -l .`, `go vet ./...`, `go test ./... -count=1`,
  `go test -race ./... -count=1`, `git diff --check`.
- Ограничение: `flock`-тест выполняется на Linux; на других платформах он
  пропускается. Real-host smoke systemd/journald остаётся проверкой E2E.

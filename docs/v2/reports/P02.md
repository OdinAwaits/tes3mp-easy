# P02 — Auth, сессии, Argon2id, CSRF

- Сделано: `panel-data/auth.json` v1 (`argon2id`, 16-byte salt, 32-byte key, `time=3`, `memory=32768`, `threads=1`, `key_len=32`); строгий парсер без неизвестных полей и битого JSON.
- Первый запуск: 24-символьный base64url-пароль, `auth.json`/`initial-password.txt` с режимом `0600`, пароль один раз попадает в лог; первый вход требует смены пароля и удаляет `initial-password.txt`.
- `reset-password [flags]`: перезаписывает хеш, создаёт новый временный пароль, печатает его в stdout; при сбое записи восстанавливает старые файлы. TLS, uploads и бэкапы не затрагиваются.
- Сессии: 32-байтный ID и CSRF-токен, in-memory map, cookie `HttpOnly`/`Secure`/`SameSite=Strict`/`Path=/`, idle 12 ч, absolute 7 дней. После смены пароля сессия и CSRF-токен ротируются; рестарт панели разлогинивает.
- CSRF: одноразовый pre-session токен для `/admin/login` в отдельной cookie на 10 минут; остальные POST принимают `_csrf` из формы или `X-CSRF-Token`. Все админские формы защищены, GET-побочек нет.
- Rate limit: 5 неудач за 15 минут на IP для логина и неверного текущего пароля, затем `429` с `Retry-After`; карта ограничена 4096 клиентами, успешный вход сбрасывает счётчик.
- Argon2 `verify` и создание нового хеша сериализованы общим семафором, чтобы не держать два буфера по 32 MiB в 64 MiB cgroup.
- Проверено: `go test ./internal/panel ./cmd/tes3mp-easy-panel`, полный `go test ./...`, `go test -race ./...`, `go vet ./...`, `go build ./...`; покрыты вход, обязательная смена, ротация, истечение, CSRF (форма/header/ошибки), cookie-флаги, rate limit, `reset-password` поверх битого `auth.json` с сохранением TLS/uploads/бэкапов и коды CLI.
- Ограничение: сессии и pre-session токены не переживают рестарт; сброс пароля требует остановленной панели; ACME и публичные маршруты в P02 не входят.

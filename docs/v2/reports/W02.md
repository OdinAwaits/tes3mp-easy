# W02 — `backups create` + retention

- Сделано: `internal/archive.WriteState` — потоковый state tar.gz без буфера
  в памяти. Пишет `players/`, `world/`, пять фиксированных `world/*/`, затем
  `requiredDataFiles.json` и канонический `current.txt`; файлы сортируются,
  uid/gid 0, mtime берётся из файлов.
- Symlink, вложенные каталоги, лишние `world/*` и нерегулярные файлы
  отклоняются. По ходу записи проверяются лимиты 50 000 записей и 1 GiB
  распакованного архива.
- CLI: `backups create --type state [--manual] [--if-running]`. Аргументы
  парсятся до lock; exclusive `flock` для записи, shared для `--dry-run`.
  `--lock-timeout=0` теперь принимается и означает одну неблокирующую попытку;
  `ErrLocked` маппится в exit 4 `locked`.
- Архив пишется в `backups/state/<name>.tar.gz.part` через `atomicfile`:
  fsync файла, rename, fsync каталога. sha256 и размер считаются по потоку;
  при ошибке `.part` удаляется, старый архив не затрагивается.
- Проверки: root и `.locks`, свободное место (<512 MiB — exit 5, <1 GiB —
  warning), имя с `-01`/`-02`, `current.txt` канонический и указывает на
  существующий mods-архив, все обязательные каталоги и метаданные state.
- `--if-running`: `systemctl is-active tes3mp.service`; stopped —
  `skipped=true`, `reason=not_running`, exit 0; недоступный systemd — exit 6.
- `--dry-run` не пишет ни байта: не создаёт state-каталог, `.part` и
  `ops.lock`, если его ещё нет; сжимает state в `io.Discard` и показывает
  будущие `archive`, `size`, `sha256`, планируемый `pruned`.
- Retention применяется после успешной записи через `retention.Apply`.
  `pruned` — реально удалённые имена, `warnings` — ошибки удаления, давления
  и превышения бюджетов. Ошибка retention не откатывает созданный архив.
- Внутренняя `createStateBackupLocked` отделена от публичной команды, чтобы
  будущие `mods deploy`/`state deploy` делали `state-predeploy-*` без
  повторного `flock` и deadlock.
- Тесты: `internal/archive/write_state_test.go`, CLI
  `cmd/tes3mp-easy-ops/backups_create_test.go`, contract
  `test/contract/ops/backups_create_test.go`; обновлены ожидания
  `--lock-timeout=0` в flags/main/contract тестах.
- Проверено: `gofmt -l .`, `go vet ./...`, `go test ./... -count=1`,
  `go test -race ./... -count=1`, `git diff --check`, cross-compile.
- Ограничение: `backups create` проверяет формат `current.txt` и наличие
  текущего mods-архива, но не пересчитывает sha256 всего mods-архива на каждом
  пятиминутном тике; это делает `state deploy`/`doctor`. Порог `no_space`
  проверяется unit-тестом с подменяемой `backupDiskFreeFunc`, а не реальным
  маленьким filesystem. Solaris собирается, но `retention.DiskFree` там явно
  возвращает ошибку: в стандартной библиотеке нет `syscall.Statfs`, а ops
  target — Linux.

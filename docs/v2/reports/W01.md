# W01 — Lock, atomicfile, pathguard

- Сделано: `internal/lock` — `flock` с режимами `Exclusive`/`Shared`,
  polling до timeout, `ErrLocked`, нулевой timeout = одна попытка,
  идемпотентный `Close`, `ErrUnsupported` без `syscall.Flock`.
- Сделано: `internal/atomicfile` — `<target>.part`, `fsync` файла, `rename`,
  `fsync` каталога; потоковый `Writer` с `Commit`/`Abort` и `WriteFile`.
- Ошибка до `rename` оставляет старый файл целым и удаляет `.part`; kill -9
  до `Commit` оставляет `.part` для `doctor`; lock-файл не удаляется.
- `pathguard` из C03 переиспользован: новые пути не появились, его тесты
  остаются покрытием имён игроков, скриптов и архивных записей.
- Тесты: `go test ./internal/lock ./internal/atomicfile`; fault-тесты
  `fsync`/`rename`/directory sync через подменяемые hooks.
- Проверено cross-compile: Linux, Darwin/arm64, FreeBSD/amd64, Windows/amd64,
  Solaris/amd64 и AIX/ppc64; на платформах без `syscall.Flock` lock возвращает
  `ErrUnsupported`.
- Ограничение: CLI-команды мутаций ещё не подключены; mapping `ErrLocked` в
  exit 4 `locked` появится в W02. `--lock-timeout=0` пока отклоняется
  парсером флагов, хотя библиотека zero timeout поддерживает.

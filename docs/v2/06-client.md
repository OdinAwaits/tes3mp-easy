# 06 — Архитектура клиента

Документ описывает поведение клиента. Схемы публичного API — в
`03-contracts.md` §7.

## 1. Роль

Клиент нужен игроку, а не админу. Его задача — довести человека от «у меня
есть папка Morrowind и бинарник» до «я в игре», не показывая терминал.

Клиент:

- находит Morrowind и проверяет обязательные ESM;
- ставит TES3MP;
- скачивает моды с панели и проверяет sha256;
- по действию пользователя ставит шрифты и общий необязательный языковой
  overlay для всех профилей;
- генерирует `openmw.cfg` и запускает игру;
- умеет запустить OpenMW-CS для продвинутых.

Клиент не:

- управляет сервером;
- делает бэкапы;
- знает SSH;
- хранит админский пароль;
- меняет оригинальную папку Morrowind.

## 2. Стек и поставка

- Go 1.24+.
- GUI — Fyne. Один бинарник, без Electron, Node.js и локального веб-сервера.
- Windows: `tes3mp-easy-client.exe`.
- Linux: `tes3mp-easy-client`.
- Без установщика и без автообновления: новая версия — новый архив.
  `.github/workflows/release.yml` собирает Linux и Windows архивы на тег `v*`;
  клиентские артефакты не входят в серверный release tar.
- Все ресурсы (иконки, тексты) встроены через `embed`.
- Fyne требует графические библиотеки (X11/Wayland/OpenGL) на Linux; это
  единственная внешняя зависимость. На Windows всё в бинарнике.

Почему Fyne: нативный файловый диалог, прогресс, кроссплатформенность и
нормальный вид без веб-слоя. Если Fyne окажется тяжёлым, UI можно заменить,
не трогая core.

## 3. Первый запуск

Мастер первого запуска состоит из пяти шагов (интерфейс английский по
умолчанию; русские строки остаются в каталоге для явной настройки):

```text
1. Папка Morrowind (автопоиск или выбор) и проверка ESM
2. Рабочая папка (по умолчанию `%LOCALAPPDATA%\tes3mp-easy` или
   `~/.local/share/tes3mp-easy`)
3. Проверка и установка TES3MP
4. Локализация (необязательно; кнопка Skip)
5. Готово → главный экран; сервер добавляется отдельно
```

Локализация — не настройка профиля, а одна глобальная необязательная установка:
пакет ставится в `workDir/localization` и подключается ко всем профилям при
запуске. Шаг можно пропустить и выполнить позже кнопкой **Localization** в
шапке. Язык интерфейса лаунчера (`language`) с этим не связан.

Сервер не входит в мастер: после завершения нажмите «Add» на главном экране и
вставьте один адрес — `host`, `host:port`, `tes3mp://host:port` или
`https://panel-host[:port]`. В диалоге есть только необязательный пароль;
имя, порт и URL панели раскрываются в «Advanced options». Пароль передаётся
TES3MP, а адрес/порт записываются в `tes3mp-client-default.cfg` перед запуском.

Назад доступна, пока не началась установка (шаги Morrowind, рабочая папка,
TES3MP и локализация). Ошибка не закрывает мастер: показываем код `T3E-…`,
причину, что сделать, кнопку «Retry» и путь к логу. Завершение мастера
записывает `setup_complete` в `config.json` и повторно не показывается.

## 4. Layout

### 4.1. Windows

```text
%APPDATA%\tes3mp-easy\config.json
%LOCALAPPDATA%\tes3mp-easy\
├── tes3mp\                 # TES3MP Win64
├── prefix\                 # не используется на Windows
├── servers\<server-id>\
│   ├── data\Data Files\    # моды сервера
│   └── openmw.cfg          # профиль; active копируется в конфиг OpenMW
├── localization\           # общий необязательный языковой overlay
│   ├── main\Data Files\
│   └── voices\Data Files\
├── cache\                  # скачанные архивы, можно чистить
└── logs\
```

### 4.2. Linux

```text
~/.config/tes3mp-easy/config.json
~/.local/share/tes3mp-easy/
├── tes3mp\
├── prefix\                 # Proton prefix
├── servers\<server-id>\
│   ├── data\Data Files\    # моды сервера
│   └── openmw.cfg          # профиль; active копируется в конфиг OpenMW
├── localization\           # общий необязательный языковой overlay
│   ├── main\Data Files\
│   └── voices\Data Files\
├── cache\
└── logs\
```

`<server-id>` — нормализованное имя (host:port → `host_port`), без слэшей и
пробелов. Один сервер = одна папка; несколько серверов не конфликтуют.

Morrowind остаётся read-only. Клиент читает `Morrowind/Data Files`, но ничего
туда не пишет. Моды — в `servers/<id>/data/Data Files`; общая локализация — в
`workDir/localization`; шрифты — в конфигурационном каталоге OpenMW (см. §9).

`servers/<id>/openmw.cfg` — это профиль, а не файл, который читает игра
напрямую. Перед запуском клиент копирует/обновляет активный `openmw.cfg`:

- Windows: `%USERPROFILE%\Documents\My Games\OpenMW\openmw.cfg`;
- Linux/Proton: `<prefix>/pfx/drive_c/users/steamuser/Documents/My Games/OpenMW/openmw.cfg`.

При переключении сервера активный конфиг перезаписывается из профиля. Старый
активный конфиг сохраняется как `.bak-<timestamp>`.

Перед запуском клиент также обновляет `tes3mp/tes3mp-client-default.cfg`:
меняются только `destinationAddress`, `port` и `password` в секции `[General]`.
Комментарии, CRLF/LF, порядок и остальные ключи сохраняются; старый файл
копируется в `tes3mp-client-default.cfg.bak-<timestamp>`, запись атомарная с
правами `0600`. Без этого шага TES3MP запускался бы с `localhost` независимо
от профиля. Пароль не попадает ни в лог, ни в отчёт диагностики.
### 4.3. `config.json`

Файл создаётся при первом сохранении в каталоге конфигурации:

```json
{
  "version": 1,
  "language": "en",
  "theme": "dark",
  "morrowind_path": "",
  "work_dir": "",
  "proton_path": "",
  "skip_fonts": false,
  "active_server": "203.0.113.10_25565",
  "servers": [
    {
      "id": "203.0.113.10_25565",
      "name": "Morrowind with friends",
      "address": "203.0.113.10",
      "port": 25565,
      "password": "******",
      "panel_url": "https://203.0.113.10"
    }
  ]
}
```

- `language` по умолчанию `en`; явное `ru` остаётся поддержанным. Это только язык
  интерфейса лаунчера.
- Локализация игры в `config.json` не хранится: это глобальная необязательная
  установка в `workDir/localization`. Устаревшие поля `game_language` и
  `localization` при загрузке игнорируются и исчезают при следующем сохранении.
- `theme` — `dark` по умолчанию, `light` или `system` (янтарная палитра).
- Пустые пути означают значения по умолчанию из §4.
- `id` вычисляется из `address:port`: нижний регистр, всё кроме латиницы,
  цифр, `.` и `-` заменяется на `_`, затем добавляется `_<port>`. Смена
  адреса или порта создаёт новый профиль-каталог; старый профиль заменяется.
- `panel_url` необязателен: пустое значение означает `https://<address>`, а
  для loopback — `http://<address>`. Если задан, это HTTPS без пути, query и
  fragment; HTTP разрешён только для `localhost`/loopback.
- `active_server` очищается, если такого `id` больше нет.
- Пароль хранится в открытом виде, поэтому файл всегда `0600`; ошибки
  валидации не печатают пароль.
- Запись атомарная через `config.json.part`. Отсутствующий файл — первый
  запуск; битый JSON, неизвестная версия, дубли `id` и неверные поля —
  ошибка запуска, а не молчаливая замена конфигурации.



## 5. Поиск Morrowind

### 5.1. Windows

1. Реестр:
   - `HKLM\SOFTWARE\WOW6432Node\Bethesda Softworks\Morrowind` → `Install Path`;
   - `HKLM\SOFTWARE\Bethesda Softworks\Morrowind` → `Install Path`.
2. Steam:
   - `C:\Program Files (x86)\Steam\steamapps\common\Morrowind`;
   - библиотеки из `steamapps\libraryfolders.vdf`.
3. GOG: стандартные `C:\GOG Games\Morrowind` и соседние варианты.
4. Если не нашли — файловый диалог.

### 5.2. Linux

1. `~/.steam/steam/steamapps/common/Morrowind`;
2. `~/.local/share/Steam/steamapps/common/Morrowind`;
3. `~/.steam/root/steamapps/common/Morrowind`;
4. Flatpak:
   `~/.var/app/com.valvesoftware.Steam/.local/share/Steam/steamapps/common/Morrowind`;
5. Если не нашли — диалог.

### 5.3. Проверка

Ищем `Data Files/Morrowind.esm`, `Tribunal.esm`, `Bloodmoon.esm`. На Windows
сравнение регистронезависимое, на Linux — сначала точное, потом
регистронезависимый поиск в пределах `Data Files`.

Если чего-то нет:

- показываем, каких файлов не хватает;
- объясняем, что нужна полная установка Morrowind, а не только `Morrowind.exe`;
- не даём продолжить, пока комплект не полный.

Реализация (`internal/morrowind`) проверяет кандидатов по порядку из §5.1/§5.2,
затем `steamapps/libraryfolders.vdf` и GOG-каталоги, и возвращает первый полный
комплект. Настроенная вручную папка проверяется первой. Имена `Data Files` и
ESM сравниваются сначала точно, затем регистронезависимо. Пакет только читает
исходную установку и никогда не пишет в неё.

## 6. Установка TES3MP

- Версия фиксируется в сборке клиента: TES3MP 0.8.1 Win64.
- URL и SHA256 зашиты в код; скачанный zip проверяется до распаковки.
- Скачивание в `cache/tes3mp-0.8.1-win64.zip`; при наличии файла в кеше он
  сначала проверяется по SHA256.
- Распаковка идёт в соседний `tes3mp.staging-<random>`, затем каталог
  заменяется; старая версия до успешной замены лежит в `tes3mp.old`, после
  успеха удаляется. Маркер `.tes3mp-version` внутри `tes3mp/` хранит
  установленную версию.
- Если `tes3mp/tes3mp.exe` уже есть и маркер версии совпадает — не качаем.
- ZIP проверяется теми же правилами, что tar: запрет абсолютных путей, `..`,
  symlink/hardlink, дублей и выхода за лимиты (512 MiB сжатых, 1 GiB
  распакованных, 10 000 записей).
- Ошибка сети: 3 попытки с паузой, затем понятное сообщение и кнопка
  «Повторить». HTTP разрешён только для loopback-тестов, публичный URL — HTTPS.

### 6.1. Windows

`tes3mp.exe` запускается напрямую. `openmw.cfg` и `settings.cfg` лежат в
`Documents\My Games\OpenMW`; платформенный адаптер создаёт их при первом
запуске, как это делает TES3MP.

### 6.2. Linux

TES3MP — Windows-бинарник, поэтому запускаем через Proton:

- ищем Proton в:
  - `~/.steam/steam/steamapps/common/Proton*`;
  - `~/.local/share/Steam/steamapps/common/Proton*`;
  - `~/.steam/steam/compatibilitytools.d/GE-Proton*`;
- если не нашли — диалог выбора папки с `proton`;
- создаём prefix в `prefix/`;
- симлинк `prefix/pfx/drive_c/Morrowind` → папка Morrowind;
- генерируем `openmw.cfg` в
  `prefix/pfx/drive_c/users/steamuser/Documents/My Games/OpenMW`;
- запускаем:

```text
SteamAppId=22320
SteamGameId=22320
STEAM_COMPAT_DATA_PATH=<work>/prefix
STEAM_COMPAT_CLIENT_INSTALL_PATH=<steam root>
<proton>/proton run <work>/tes3mp/tes3mp.exe
```

Proton не скачиваем и не устанавливаем: это часть Steam. Если Proton нет,
клиент объясняет, откуда его взять, и даёт выбрать путь вручную.

## 7. Карточка сервера

Минимальные поля:

```json
{
  "name": "Morrowind with friends",
  "address": "203.0.113.10",
  "port": 25565,
  "password": "******",
  "panel_url": "https://203.0.113.10"
}
```

- Адрес и порт проверяются: порт 1..65535, адрес не пустой. В одном поле можно
  вставить `host`, `host:port`, `tes3mp://host:port` или
  `https://panel-host[:port]`.
- `panel_url` необязателен и выводится из адреса; явное значение — HTTPS, кроме
  localhost (для разработки). HTTP для публичного API не принимается.
- Статус панели (`GET /api/v1/server`) проверяется автоматически и показывается
  внутри карточки сервера; отдельной кнопки «Проверить» нет.
- Если сервер недоступен, профиль можно сохранить: статус покажет `T3E-NET-…`,
  а запуск и обновление модов останутся доступными.
- Пароль хранится в `config.json` (права `0600`) в открытом виде: системный
  keyring не используется. Это осознанный компромисс для одного домашнего
  сервера; пароль не логируется и не попадает в отчёты об ошибках. Перед
  запуском он записывается в `tes3mp-client-default.cfg` (тоже `0600`).

Адрес и параметры сервера передаются вручную. Ссылки
`tes3mp-easy://connect?...` и файлы `.tes3mp-easy` не поддерживаются; сценарий
«скинул адрес в мессенджере» закрывается ручным вводом.

`internal/serverapi` реализует только публичные GET-запросы §7: строгий JSON,
лимит ответа 1 MiB, HTTPS (HTTP — только loopback), таймауты и три попытки на
сеть/5xx. Ответ `no_mods` сохраняется как `ErrNoMods`. URL архива обязан
остаться на хосте панели и указывать на фиксированный путь; редирект на другой
хост отклоняется. Пароль сервера и админские cookie в клиент API не попадают.

## 8. Моды

Алгоритм:

1. `GET /api/v1/mods/current` → `{name, sha256, size, url}`.
   В поддерживаемой установке `bootstrap` создаёт `current.txt` и
   `mods-init-*`, поэтому `404` (`no_mods`/`not_found`) — это ошибка установки,
   а не «сервер без модов»: показываем причину и не начинаем установку.
2. Сравнить `sha256` с установленным в `servers/<id>/.mods-sha256`.
3. Если совпадает — пропустить.
4. Скачать архив в `cache/` с прогрессом, проверить sha256 и размер.
5. Распаковать в `servers/<id>/.staging/`.
6. Проверить:
   - есть `plugins/`;
   - нет опасных путей;
   - базовые ESM из `requiredDataFiles.json` присутствуют в Morrowind, а
     остальные файлы — в распакованном архиве;
   - расширения из белого списка.
7. Собрать новый `Data Files`: скопировать плагины из staging.
8. Сгенерировать профиль `servers/<id>/openmw.cfg`.
9. Атомарно заменить `data/Data Files` и профиль `openmw.cfg`; старые — в
   `.old`.
10. Записать `.mods-sha256`.
11. Удалить staging и старые каталоги.

`internal/mods` выполняет шаги 2–11. Кеш проверяется по имени, размеру и SHA256;
имя обязано проходить `mods-*`/`mods-init-*`. Скачивание идёт потоково в
`cache/<name>.part` через `atomicfile`, затем архив проверяется общим
`internal/archive`, распаковывается в `servers/<id>/.staging/`, а базовые ESM
сверяются с Morrowind по CRC из `requiredDataFiles.json`. `Data Files` и
`openmw.cfg` заменяются через `*.old`; digest пишется последним. Любая ошибка
до digest возвращает прежние файлы. Серверные `scripts/` не копируются.

`openmw.cfg`:

```text
fallback-archive=Morrowind.bsa
fallback-archive=Tribunal.bsa
fallback-archive=Bloodmoon.bsa
data="<Morrowind>/Data Files"
data="<work>/servers/<id>/data/Data Files"
content=Morrowind.esm
content=Tribunal.esm
content=Bloodmoon.esm
content=<mod.esp>   # порядок из requiredDataFiles.json
```

При сборке профиля и активного `openmw.cfg` не перезаписываем файл целиком:
сохраняем `encoding`, `fallback`, `Fonts_Font_*` и другие пользовательские
строки, заменяем только `data=` и `content=`. Если установлен глобальный
языковой overlay, `PrepareConfig` добавляет
`data="<work>/localization/main/Data Files"` после первого базового `data=` и
до `data=` модов сервера, а прежнюю управляемую строку удаляет. Сам профиль
`servers/<id>/openmw.cfg` при этом не меняется. Перед заменой — `.bak-<timestamp>`.
Активный конфиг обновляется из профиля перед запуском (§4).

`requiredDataFiles.json` обязателен. Если его нет, архив невалиден: установка
не начинается, потому что сервер откажет по CRC. Если плагин из JSON
отсутствует — та же ошибка.

Серверные `scripts/` клиенту не нужны; они остаются на сервере.

## 9. Шрифты

Шрифты — главная причина «квадратиков» и боли новичка. Поэтому они
ставятся автоматически, без выбора из 12 вариантов.

- Клиент скачивает фиксированный набор (sans/serif/mono) с зашитыми URL и
  SHA256; источник — Google Fonts (OFL) или GitHub Releases проекта. Панель
  шрифты не раздаёт.
- Файлы кладутся в `Fonts/` конфигурационного каталога OpenMW
  (`.../My Games/OpenMW/Fonts`), а не в Morrowind и не в
  `servers/<id>/data/`.
- `Fonts/openmw_font.xml` генерируется рядом с TTF в `Fonts/`, а не в корне
  конфигурационного каталога OpenMW, с диапазонами Latin + Cyrillic.
- В `openmw.cfg` добавляются/обновляются `fallback=Fonts_Font_0,...`,
  `Fonts_Font_1,...`, `Fonts_Font_2,...`.
- Если скачать не удалось, клиент всё равно запускает игру со стандартным
  шрифтом и показывает предупреждение, а не блокирует запуск.
- Продвинутый выбор шрифтов не реализован: отдельного чекбокса нет. Шрифты
  ставятся автоматически вместе с локализацией и перепроверяются перед каждым
  запуском. `skip_fonts` остаётся только как legacy-поле конфига и не
  показывается в интерфейсе.

Реализация `internal/fonts` использует `NotoSans.ttf`, `NotoSerif.ttf` и
`RobotoMono.ttf` из `google/fonts`; URL и SHA256 зашиты в
`internal/fonts/fonts.go`. Скачивание идёт через общий `internal/download` в
`cache/fonts/`, файлы устанавливаются атомарно, а `Fonts/openmw_font.xml` и
`fallback=Fonts_Font_0..2` обновляются идемпотентно. Неудачный файл попадает в
предупреждения, остальные шрифты и запуск продолжают работать.

## 10. Локализация

Локализация — глобальная необязательная установка, а не настройка профиля и не
поле `config.json`. Один пакет используется всеми профилями. Язык интерфейса
лаунчера (`language`) с ним не связан: интерфейс по умолчанию английский.

Кнопка **Localization** в шапке и необязательный шаг мастера:

1. Показывают список доступных пакетов из `internal/locale` (сейчас только
   Russian; всегда текст + озвучка).
2. Скачивают только выбранный пакет, показывают прогресс и результат. При
   ошибке доступны **Retry** и **Back**; ранее установленный пакет не
   затрагивается.
3. После успеха ставят кириллические шрифты. Ошибка шрифтов — предупреждение,
   локализация остаётся установленной.

- Оригинальная папка Morrowind не изменяется. Пакет собирается в
  `workDir/localization/main/Data Files` и `voices/Data Files` и подключается
  через `data=` только в активном `openmw.cfg` при запуске.
- Строка overlay добавляется после базового `data=` Morrowind и до `data=` модов
  сервера, поэтому локализация перекрывает базовые файлы, но серверные моды
  сохраняют приоритет. При повторном запуске managed-строка заменяется, а не
  дублируется.
- Для `russian` в активный `openmw.cfg` ставится `encoding=win1251`. Если пакет
  не установлен, encoding берётся из самого `Morrowind.esm`: CP1251
  определяется по маркерам в ESM. Это сохраняет вручную локализованные
  установки и не требует поля в конфиге.
- Пакет собирается транзакционно: архивы скачиваются и проверяются во временном
  каталоге, затем атомарно подменяют `workDir/localization`; старый пакет
  сохраняется до успешной подмены. Повторная установка того же пакета
  пропускается.
- Отдельного «возврата на English» нет: English не является пакетом. Удаление
  overlay (API `RemoveLocalization`) возвращает все профили к оригинальному
  языку Morrowind; в GUI действие удаления не показывается.
- Если пакет не установлен, запуск не блокируется: используется оригинальный
  Morrowind. Ошибка установки локализации не влияет на уже установленный пакет.

`internal/locale` скачивает `russian.tar` и `voices_russian.tar` в `cache/`,
проверяет SHA256 и собирает `localization/main` и `voices` через
`internal/archive`. `mapEntry` берёт только `Data Files/` и legacy `Video/`,
`Sound/`, `Music/`, отбрасывая launcher-файлы. `UpdateDataFiles` отвечает за
идемпотентную вставку/удаление managed-строки в активном конфиге.

## 11. Запуск

Перед запуском клиент проверяет:

1. Morrowind и три ESM на месте.
2. `tes3mp.exe` на месте.
3. `openmw.cfg` существует и содержит корректные `data=`/`content=`.
4. Моды соответствуют `mods_sha256` с панели (если панель доступна).
5. На Linux — Proton и prefix.
6. Если установлен глобальный языковой overlay, его `data=` и encoding
   добавляются в активный `openmw.cfg`; сам профиль не меняется.

Если моды устарели:

- онлайн: скачиваем и ставим новую версию с прогрессом;
- офлайн: предлагаем запустить с текущими модами и предупреждаем, что сервер
  может отказать.

Запуск:

- Windows: `tes3mp.exe` с рабочим каталогом `tes3mp/`;
- Linux: `proton run tes3mp.exe` с env из раздела 6.

Клиент запускает игру и ждёт завершения процесса в фоне, не блокируя UI:
показывает «Игра запущена», а после выхода пишет «Игра закрыта» и предлагает
открыть лог.

OpenMW-CS:

- кнопка «OpenMW-CS» в advanced-разделе;
- запускает `openmw-cs.exe` из установленного TES3MP/OpenMW, если он есть;
- если нет — объясняет, что CS не входит в клиент, и даёт ссылку.

`internal/launcher` проверяет Morrowind и TES3MP, находит Proton, создаёт
`prefix` и symlink `C:\Morrowind`, готовит активный `openmw.cfg` из профиля и
формирует `Spec`. Windows запускает `tes3mp.exe` напрямую; Linux — `proton run`
с `SteamAppId=22320`, `SteamGameId=22320`, `STEAM_COMPAT_DATA_PATH` и
`STEAM_COMPAT_CLIENT_INSTALL_PATH`. Процесс запускается без ожидания; UI ждёт
его в отдельной goroutine и показывает результат выхода.

## 12. GUI

Fyne-окно с янтарной тёмной/светлой темой (переключается в Settings; выбор
хранится в `theme`). Интерфейс по умолчанию английский.

- **Servers** — карточки профилей. На карточке один основной CTA: «Play»,
  «Download mods and play» или «Update and play». Бейджа языка игры больше нет.
  Статус панели проверяется автоматически и показывается inline; отдельных
  кнопок «Проверить» и «Сделать активным» нет — активным становится сервер,
  который запускают.
- **More** — открыть панель, обновить моды (повторная установка), Advanced
  (включая OpenMW-CS), изменить или удалить профиль.
- **Localization** — глобальная установка языкового пакета для всех профилей;
  не привязана к карточке сервера.
- **Setup** — мастер из пяти шагов (Morrowind, рабочая папка, TES3MP,
  локализация с кнопкой Skip, готово); открывается сам, если `setup_complete`
  не записан, и повторно из Settings.
- **Progress** — скачивание/распаковка; один диалог на всю цепочку
  «моды → запуск».
- **Settings** — тема, путь Morrowind, рабочая папка, Proton (Linux),
  «открыть лог». Локализации и шрифтов здесь нет: это отдельное действие
  установки.
- **Logs** — последние 300 строк, «Обновить», «Открыть папку».
- **About** — версия клиента, версия TES3MP, ссылка на проект.

Фоновые проверки никогда не открывают модальное окно: ошибка появляется в
строке статуса карточки с кодом. Модальный диалог ошибки открывается только
для действия пользователя и содержит:

```text
T3E-ENV-01
Morrowind was not found.
What to do: Select the folder that contains Data Files/Morrowind.esm…

Technical details ▸ (код, исходный текст ошибки, путь к логу)
[Retry] [Open log] [Copy report] [Settings]
```

`Copy report` копирует отчёт (`code`, `kind`, версия, платформа, пути, список
серверов без паролей, последние строки лога); известные пароли и строки
`password = …` заменяются на `[redacted]`. Лог содержит `code=T3E-…`, поэтому
его можно фильтровать без привязки к тексту интерфейса.

Коды стабильны и не переводятся:

| Домен | Коды |
|---|---|
| `ENV` | `01` Morrowind не найден, `02` неполный, `03` не выбран, `04` рабочая папка, `05` файловая система |
| `NET` | `01` сеть, `02` таймаут, `03` сертификат |
| `API` | `01` ошибка панели, `02` некорректный ответ, `03` нет модов |
| `MOD` | `01` моды не установлены |
| `LOC` | `01` локализация не установлена (legacy, теперь запуск не блокируется) |
| `GAME` | `01` TES3MP не установлен, `02` Proton, `03` конфигурация, `04` запуск, `05` игра завершилась |
| `APP` | `99` неизвестная ошибка |

Языки интерфейса: English (по умолчанию) и Русский. Строки — в
`internal/i18n`, без внешних сервисов перевода.

## 14. Безопасность

- Скачивание только по HTTPS; сертификат панели проверяется системными
  корнями. Штатная панель использует сертификат Let's Encrypt для публичного IP,
  поэтому дополнительный импорт не нужен. Если установка использует готовую
  самоподписанную пару (`--tls-mode files`), клиент показывает отдельную ошибку
  «сертификат не доверен»; молча отключать проверку нельзя.
- SHA256 для TES3MP, модов, шрифтов и локализации; без совпадения — стоп.
- Распаковка tar/zip: запрет абсолютных путей, `..`, symlink, hardlink.
- Никаких `sh -c`, `cmd /c` и подстановки имён файлов в команды.
- Пароль сервера не логируется и не попадает в отчёты об ошибках.
- `config.json` с правами `0600`; на Windows — в `%APPDATA%` пользователя.
- Клиент не принимает команды от панели: только читает публичные GET-эндпоинты.
- Клиент не хранит админский пароль и не имеет доступа к systemd.

## 15. Тестирование

| Уровень | Что проверяет |
|---|---|
| Unit | поиск Morrowind (registry/Steam VDF/GOG/Flatpak), проверка ESM, парсинг ответов API, `openmw.cfg`, sha256, pathguard |
| Unit (fixtures) | безопасная распаковка ZIP/TAR, `requiredDataFiles.json`, глобальный localization overlay и вставка `data=` |
| Integration | фейковая панель `httptest`, скачивание и установка мод-пака |
| Platform | Windows registry/Steam paths (build tags + фикстуры), Linux Proton discovery |
| Smoke | чистая Windows VM и Linux с Proton: мастер → игра |
| Regression | обновление мод-пака, офлайн-запуск, битый архив, отсутствующий ESM |

GUI-тесты не гоняем в CI: Fyne требует дисплея. Логика живёт в `app` и
тестируется без окна. `.github/workflows/release.yml` собирает клиент на
`ubuntu-latest` и `windows-latest` (CGO + MinGW), поэтому ошибки компиляции
платформенных файлов ловятся до релиза. Ручной smoke — обязательная часть
релиза:

1. Windows 10/11: чистый пользователь, бинарник + Morrowind, мастер из пяти
   шагов, добавление сервера одним адресом, установка модов, запуск игры;
   проверить, что `tes3mp/tes3mp-client-default.cfg` содержит адрес, порт и
   пароль, а не `localhost`.
2. Linux + Proton: автопоиск Morrowind/Proton, prefix, запуск `tes3mp.exe`.
3. Офлайн: клиент показывает понятную ошибку с `T3E-…` и не запускает
   vanilla-сервер молча.
4. Битая панель/`current.txt`: сообщение содержит действие и путь к
   `logs/client.log`; `Copy report` не содержит пароль.
5. Обе темы (Amber dark/light) и повторное открытие настроек сохраняют выбор.

## 16. Non-goals клиента

- macOS;
- автообновление клиента;
- встроенный браузер модов;
- несколько игроков/аккаунтов на одном ПК;
- управление сервером, бэкапы, SSH;
- модификация оригинального Morrowind;
- установка Morrowind или пиратских сборок;
- поддержка TES3MP 0.8.1+ с другим API без отдельного релиза;
- телеметрия и аналитика.

## 17. Критерии готовности

- Чистая Windows 10/11: бинарник + Morrowind → мастер → игра, без терминала.
- Linux: то же, с автоматическим поиском Proton и понятной ошибкой, если его
  нет.
- Моды обновляются автоматически при изменении `mods_sha256`.
- Оригинальная папка Morrowind не меняется (проверяем хешами до/после).
- Ошибки содержат действие и путь к логу.
- Клиент не требует прав администратора, кроме случаев, когда пользователь
  сам выбрал защищённую рабочую папку.

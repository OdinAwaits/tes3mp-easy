# BL-015. Прогресс установки TES3MP показывает 100% до начала скачивания

**Статус:** сделано (28.10.2026). `progressFraction` возвращает 0 для
`StageDownloading` с `Total <= 0`; начальная подпись — новый ключ
`setup.starting`. Бесконечная полоса (опциональный пункт) не делалась.

**Симптом.** При установке TES3MP полоса прогресса на мгновение заполняется до
100% и только потом начинает расти с нуля, когда пошла загрузка. В диалоге из
Installation полная полоса видна под подписью «Проверка архива TES3MP…», в
мастере — под «Скачивание 0 B / ?», то есть 100% показаны раньше первой
порции байтов.

**Причина.**

- `installTES3MP` перед загрузкой отправляет пустое событие
  `Progress{Stage: StageDownloading}` без счётчиков —
  `internal/tes3mp/install.go:131`; реальные байты приходят только из
  `download.go:166-181`.
- `progressFraction` (`internal/ui/setup.go:10-22`) возвращает `1` для любой
  стадии, кроме `StageDownloading`, и для `StageDownloading` с `Total <= 0`.
  Пустое стартовое событие попадает во второе условие — полоса прыгает на 100%.
  Тест это поведение закрепляет: `internal/ui/ui_test.go:277-291` («unknown
  total» → 1).
- Мастер сначала ставит 0 (`internal/ui/wizard.go:603-610`), но первое же
  событие из сервиса возвращает 1. Диалог Installation вообще не выставляет
  начальное значение (`internal/ui/screen_install.go:441-461`); `ProgressBar`
  по умолчанию 0, но подпись над ним — `KeySetupVerifying`
  («Проверка архива TES3MP...», `:444`), хотя проверка идёт после загрузки
  (`install.go:139`).
- Завершение на 100% в обоих местах выставляется явно
  (`wizard.go:632-633`) или приходит из последнего байтового события, поэтому
  отдельная правка «добить до 100%» не нужна.

**Что делать.**

- Разделить «неизвестно» и «готово» в `progressFraction`: для
  `StageDownloading` с `Total <= 0` возвращать `0`. Остальные стадии
  (`Verifying`, `Extracting`, `Installing`) — это уже конец загрузки, им можно
  оставить `1`, чтобы полоса не откатывалась назад.
- Тест `TestProgressFraction`: «unknown total» → `0`, остальные случаи без
  изменений (`ui_test.go:277-303`).
- Начальную подпись сделать нейтральной: новый ключ `setup.starting`
  («Подготовка загрузки TES3MP…») в оба каталога
  (`internal/i18n/catalog.go:294`, `:936`) и в `screen_install.go:444` вместо
  `KeySetupVerifying`; в мастере `tes3mpStatus` до первого события тоже
  показывает этот текст.
- Опционально: пока `Total == 0`, показывать `widget.NewProgressBarInfinite()`
  вместо детерминированной полосы и переключаться на детерминированную, когда
  пришли байты — тогда «0%» не выглядит зависшим. Минимальный вариант (без
  переключения виджетов) — только исправление `progressFraction`.
- Проверить кэш: при попадании в кэш (`cached = true`, `install.go:124-130`)
  события `StageDownloading` нет вовсе, сразу идёт `StageVerifying` с 100% —
  это корректно, но текст «Подготовка загрузки» там не должен появляться:
  ставить его только до первого события.
- Документация: §12 («Progress — скачивание/распаковка», `docs/v2/06-client.md:558`)
  дополнить строкой, что 100% появляется только после загрузки.

**Как проверять.** Установка TES3MP из Installation и из мастера без кэша:
полоса стартует с 0 и растёт; 100% видно только на проверке/распаковке после
загрузки. Установка с уже скачанным архивом: сразу проверка и 100%, без
«моргания» нулём. `go test ./internal/ui ./internal/tes3mp` зелёный,
`progressFraction` покрыт таблицей.

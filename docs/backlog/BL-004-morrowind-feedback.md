# BL-004. Morrowind: отсутствие, поиск и проверка без «ошибки»

**Статус:** новое (28.10.2026), не начато. Включает BL-014 («Найти
автоматически» и «Проверить файлы»: нет обратной связи).

**Симптом.**

- На первом запуске мастер сам ищет Morrowind, не находит и рисует в шаге блок
  ошибки с кодом `T3E-ENV-01` («Morrowind не найден»), а «Далее» остаётся
  заблокированной. То же при «Играть»: сначала скачиваются моды, и только потом
  вместо подсказки открывается полноэкранный диалог ошибки с кодом и кнопкой
  «Повторить». Если игры на машине нет, это не ошибка, а незавершённая
  настройка.
- Кнопки «Найти автоматически» и «Проверить файлы» не показывают, что идёт
  работа: строка статуса пустая, кнопки остаются активными, повторный клик молча
  игнорируется. Поиск по стандартным путям и Steam-библиотекам занимает
  секунды, всё это время экран выглядит мёртвым. Автопоиск при входе на шаг
  вообще не заметен. Ошибка появляется только в конце и выглядит как
  технический английский блок со списком проверенных путей.

**Причина.**

- Шаг Morrowind при входе вызывает `detectMorrowind`
  (`internal/ui/wizard.go:457-483`), при провале — `setProblem(err, ...)`, а тот
  печатает `failureBody` с кодом `T3E-ENV-01`. Пройти шаг нельзя: `canAdvance()`
  (`internal/ui/wizard.go:315-318`) требует `morrowindReady`. При «Играть» без
  настроенной игры `app.Launch` возвращает `ErrMorrowindNotConfigured`
  (`internal/app/launch.go:119-121`), а если путь задан, но пуст —
  `morrowind.ErrNotFound` из `launcher.Resolve`
  (`internal/launcher/paths.go:128`), и UI показывает `showErrorWithRetry`
  (`internal/ui/launch.go:93`), причём моды к этому моменту уже скачаны. На
  «Установке» тот же факт уже показан как предупреждение (`morrowindStatus`,
  `internal/ui/screen_install.go:175-195`).
- `morrowindObjects` создаёт `morrowindStatus` пустым и три кнопки без
  сохранения ссылок: `internal/ui/wizard.go:168-186`. Текст статуса ставится
  только при успехе (`:476-479`) или через `setProblem` при ошибке (`:470`).
- `detectMorrowind` и `checkMorrowind` асинхронны, но `beginBusy`/`endBusy`
  (`:393-405`) меняют лишь `next`/`back` в `updateButtons` (`:288-313`);
  `find`, `choose`, `check` не блокируются, а второй клик отбрасывается
  (`beginBusy` возвращает false, `:458`, `:495`).
- Вход на шаг запускает автопоиск молча: `enterStep` (`:432-441`) вызывает
  `detectMorrowind` без сообщения, а `morrowindAttempted` запрещает повтор.
  `Discover` перебирает настроенный путь и стандартные кандидаты, включая
  Steam-библиотеки (`internal/morrowind/discover.go:60-99`) — это файловые
  операции, а не мгновенная проверка.
- Текст ошибки — Go-строка на английском: `NotFoundError.Error` перечисляет до
  шести путей (`internal/morrowind/morrowind.go:80-100`), затем `failureBody`
  оборачивает её в код/что/что делать (`internal/ui/failure.go:119-135`).
  Короткой локализованной строки «не найдено, выберите папку» нет.
- На экране Installation этих действий нет вовсе: строка Morrowind умеет только
  «Сменить папку» и открывает мастер (`internal/ui/screen_install.go:60-64`),
  поэтому искать и проверять можно только внутри мастера.

**Что делать.**

1. Классификация: провал автопоиска — подсказка `widget.WarningImportance`
   («Morrowind не найден, укажите папку») без кода ошибки и без «Повторить»;
   повтор даёт кнопка «Найти». `canAdvance()` для шага Morrowind — `true`: шаг
   не блокирующий, мастер можно закончить без игры.
2. «Играть» без Morrowind — не диалог ошибки, а переход в «Установку» с
   подсветкой строки Morrowind (`showScreen(screenInstall)`), текст в духе
   «Укажите папку Morrowind, чтобы играть». Механизм уже есть: `launchRefusal`
   (`internal/ui/launch.go:121-131`) превращает часть ошибок в обычное
   уведомление; добавить туда `ErrMorrowindNotConfigured` и
   `morrowind.ErrNotFound`. Проверку Morrowind поднять до скачивания модов.
3. Обратная связь: перед горутиной ставить в `morrowindStatus` новый ключ «Ищу
   Morrowind…» / «Проверяю папку…» и очищать при завершении; два ключа в оба
   каталога (`internal/i18n/catalog.go:283-294`, `:925-936`).
4. Индикатор: `widget.NewProgressBarInfinite()`
   (`widget/progressbarinfinite.go:198`) под рядом кнопок, `Show()` в
   `beginBusy`, `Hide()` в `endBusy`. Для трёх секунд ожидания этого
   достаточно, процент показывать нечем.
5. Заблокировать сами действия: хранить `morrowindActions []fyne.Disableable` в
   `setupWizard` и в `beginBusy`/`endBusy` вызывать `Disable()`/`Enable()`
   вместе с `updateButtons`; `*widget.Button` реализует `fyne.Disableable`.
6. Ошибку разделить на короткую строку и детали: в статус — «Morrowind не найден
   — укажите папку вручную», в `problem` — текущий `failureBody` с путями и
   логом. Для `NotFoundError` Retry не нужен: повторный автопоиск даст тот же
   результат, полезнее «Выбрать папку…». Ошибками с кодом остаются случаи, где
   пользователь уже что-то указал: `morrowind.ErrIncomplete`, `ErrProton`,
   `ErrWorkDir`.
7. Автопоиск при входе на шаг оставить, но с тем же статусом «Ищу…»; если не
   нашлось — не блокировать шаг, а подсветить путь и кнопку выбора.
8. Installation: продублировать «Найти автоматически» рядом со «Сменить папку»
   (тот же вызов `DetectMorrowind` через `app.Service`), чтобы действие было там,
   где пользователь ищет проблему. Пересечение с BL-003 — использовать общий
   `chooseFolder()` оттуда.

**Как проверять.** Чистый `config.json` без Morrowind: мастер открывается на
шаге Morrowind, показывает предупреждение, «Далее» активна, красного блока и
кода нет; «Играть» ведёт в «Установку». Нажать «Найти автоматически» с пустым
путём: сразу видна строка «Ищу…», кнопки серые, барабан бежит; при находке —
«Morrowind готов: <путь>», при неудаче — короткая строка и детали. То же для
«Проверить файлы» с заведомо неполной папкой; быстрый двойной клик не запускает
два поиска; пустая папка, выбранная вручную, всё ещё даёт `T3E-ENV-01`. Тесты:
`beginBusy()` выключает три кнопки и включает индикатор, `endBusy()` возвращает
обратно; `internal/app/failure_test.go` (классификация); драйвер Fyne
(`testShell`, `internal/ui/screen_test.go:18`) — в шаге нет
`KeyErrorMorrowindNotFound`, статус виден.
